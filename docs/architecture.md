# Architecture

## Components

| Path | Role | Depends on |
|---|---|---|
| `SPECIFICATION.md` | The convention, grid, digit table, JSON contract v1, CLI protocol and manifest format. | — |
| `fixtures/known-values.json` | **Ground truth**, transcribed by hand. It covers all 36 digit/corner motifs, King's six printed composites and owner-reviewed examples. It is never generated by code. | — |
| `judge/geometry.py` | Strict JSON parsing, contract validation and normalization to sets of edges. | standard library |
| `judge/reference.py` | The reference encoder: a units-motif table plus two reflections. | standard library |
| `judge/runner.py` | Builds and runs each implementation from its manifest, then compares the output with the reference. | geometry, reference |
| `implementations/<lang>/` | Independent encoders, each with a CLI adapter and a `manifest.json`. They never import the judge. | own toolchain |
| `web/` | Static Vite + TypeScript site that draws glyphs with SVG. | `implementations/typescript/src/encoder.ts`, through the `cistercian-encoder` alias |
| `scripts/render_digit_chart.py` | Generates `docs/digit-chart.svg` and `docs/example-1986.svg` from the reference encoder. | reference |
| `scripts/test-all.sh` | Runs every check locally. | all of the above |

## Why the reference is not the oracle on its own

If a digit were transcribed wrongly, a reference encoder and every implementation copied from it would still agree perfectly. So the reference is tested against the hand-written fixtures.

The tests also prove the fixtures would catch real mistakes. They swap each digit's shape for every other digit's shape, including the historically confusing 6 and 8, and they apply the wrong reflection to a quadrant. Every one of these mutations fails the fixture tests.

## Test layers

| Layer | Where |
|---|---|
| Contract and normalizer | `judge/tests/test_geometry.py`, `test_schema.py` |
| Verified fixtures and mutation tests | `judge/tests/test_fixtures.py` |
| Reference unit tests (digit splitting, symmetry, all 9,999 numbers distinct) | `judge/tests/test_reference.py` |
| Runner behaviour, using a fake implementation that breaks the protocol one way at a time | `judge/tests/test_runner.py` |
| Conformance of each implementation: all 9,999 numbers in order and shuffled, plus 25 invalid-input and edge cases | `python -m judge.runner` |
| Website: the alias resolves to the real encoder, `web/src` contains no glyph data, pixel mapping, input validation | `web/src/web.test.ts` |
| Generated SVGs are up to date | `judge/tests/test_chart.py` |

## Website

```bash
cd web
npm ci
npm run dev      # development server
npm test         # Vitest
npm run build    # static site in web/dist/
```

The page has two input views:

- **Type:** a text box plus example buttons.
- **Dials:** four rolling digit wheels (`web/src/dial.ts`), each placed beside the corner it controls. Turning a wheel highlights that corner's strokes, which come from the encoder's `digitSegments`.

The SVG renderer (`web/src/render.ts`) is presentation only. It maps grid coordinates to pixels and draws exactly the segments the encoder returns. It has no knowledge of which strokes make up a digit.

Vite's `base: "./"` makes every asset URL relative, so `web/dist/` works at a GitHub Pages project URL without knowing the repository name.

## CI and deployment

| Workflow | Trigger | Jobs | Permissions |
|---|---|---|---|
| `.github/workflows/test.yml` | pull requests, including from forks; pushes to branches other than `main`; called by `deploy.yml` | Python 3.10 and 3.13 (judge tests, SVG check, Python conformance); TypeScript conformance on Node 20.19 and 24; website tests and build | `contents: read` only |
| `.github/workflows/deploy.yml` | pushes to `main`, or a manual run | runs the full `test.yml`, then builds the site, then deploys to Pages | the deploy job alone gets `pages: write` and `id-token: write` |

Actions are pinned to commit SHAs, and checkouts don't keep credentials. No workflow uses `pull_request_target` or any secrets.

CI runs only code that is already in this repository. It is not a sandbox for untrusted code.
